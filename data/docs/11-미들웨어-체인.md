# 미들웨어 체인

## 개요

Nuxt 3의 전역 미들웨어가 모든 라우트 이동 시 순서대로 실행된다. SSR과 CSR 양쪽에서 실행되며, 각 미들웨어는 무한 루프 방지 로직을 포함한다.

```
요청 → 01.site-init → 01b.layout → 02.auth → 03.menu → 04.permission → 06.color-mode → 페이지
```

## 01. site-init — IP 접근 제어 + 사이트 감지

파일: `middleware/01.site-init.global.ts`

**가장 먼저 실행되어야 하는 미들웨어.** 다른 미들웨어(auth/menu/layout)보다 먼저 IP를 검증한다.

### 동작

```
SSR:
  1. X-Forwarded-For에서 클라이언트 IP 추출
  2. 사이트 설정의 allowIp/denyIp 패턴과 CIDR 매칭
     - Allow 우선 정책: allowIp에 매칭되면 통과
     - 그 외 denyIp 체크 ("all" 또는 "0.0.0.0/0"이면 전체 차단)
  3. 차단 시: __ipBlock=1 쿠키 설정 + 403 에러 throw (렌더링 중단)
  4. URL 경로에서 사이트명 추출 → siteStore.setSite()

CSR:
  1. __ipBlock 쿠키 확인
  2. 쿠키 있으면 403 에러로 네비게이션 중단
```

### SSR/CSR 일관성

SSR에서 `__ipBlock=1` 쿠키를 설정하여 CSR 하이드레이션 시에도 동일한 차단 상태를 유지한다. matchIp() 유틸로 CIDR 매칭.

## 01b. layout-setting — 레이아웃 자동 선택

파일: `middleware/01b.layout-setting.global.ts`

**리다이렉트 없이 메타데이터만 설정하는 미들웨어.**

### 동작

```
1. URL에서 사이트명 추출 (/www/notice → "www")
2. slugify()로 레이아웃 프리픽스 생성
3. import.meta.glob()으로 물리 레이아웃 파일 Set 구축
4. URL 깊이로 main/sub 결정:
   - /site → main
   - /site/... → sub
   - / (루트) → www-main 또는 default
5. business → 항상 "business-sub" (main/sub 구분 없음)
6. to.meta.layout = "{prefix}-{main|sub}"
7. 폴백 체인: {prefix}-main → default-main → default-sub → default
```

메뉴 트리와 완전히 독립적. 다른 미들웨어에 의존하지 않는다.

## 02. authentication — 사이트 개폐 + 관리자 체크

파일: `middleware/02.authentication.global.ts`

### 동작

```
사이트가 닫힌 경우 (isOpen=false):
  ├─ 게스트:
  │   SSR: 302 → 로그인 페이지 (msg=AUTH.ADMIN.ONLY.LOGIN, redirect=현재URL)
  │   CSR: showAlertMessage + navigateTo(로그인, replace: true)
  │
  ├─ 비관리자 (로그인된 일반 사용자):
  │   SSR: 302 → /www (msg=AUTH.ADMIN.ONLY)
  │   CSR: showAlertMessage + navigateTo(/www, replace: true)
  │
  └─ 관리자: 통과

사이트가 열린 경우: 무조건 통과
```

### 루프 방지

- `redirected=1` 쿼리 파라미터: 이미 리다이렉트된 요청 재처리 방지
- SSR: `useState()` 플래그로 렌더당 1회만 리다이렉트

## 03. menu-management — 경로 정규화 + 메뉴 로드 + 폴더 리다이렉트

파일: `middleware/03.menu-management.global.ts`

### 동작

```
1. 경로 정규화
   //foo/bar/ → /foo/bar (중복 /, 후행 / 제거)
   SSR: 301 리다이렉트 (하이드레이션 안전)
   CSR: 별도 처리 불필요 (클라이언트 라우팅)

2. 메뉴 트리 로드
   lastLoadedSite와 비교하여 사이트 변경 시만 재로드
   menuStore.fetchMenuTree(site) — 에러 시 조용히 무시 (500 방지)

3. 로컬 메뉴 보강
   pathUrl 또는 routePath로 라우트 경로 생성
   스토어 상태 오염 없이 요청 단위로 처리

4. 현재 메뉴 매칭
   findMenuByPath()로 정규화된 URL과 메뉴 트리 매칭
   menuStore.setCurrentMenuByPath(path)

5. 폴더/컨테이너 메뉴 처리
   type=folder인 메뉴에 도달 시:
   → 첫 번째 보이는(isShow) 자식 메뉴로 리다이렉트
   → getEffectiveRoutePath()로 실제 경로 해석
   → treatLinkAsFolder 옵션도 지원

루프 방지: useState("__ssr_menu_redirected__") — SSR 렌더당 1회
```

## 04. permission-check — 렌더 데이터 + 권한 검증

파일: `middleware/04.permission-check.global.ts`

### 스킵 조건

- 사이트 루트 페이지 (예: `/www`)
- currentMenuId 없음 (메뉴 매칭 실패)
- /common/* 영역 (로그인 등)

### 동작

```
1. renderStore.fetchRenderData() 호출
   GET /back-api/render (X-Menu-Id, X-Site-Hostname 헤더 포함)
   → type, value, option(게시판 설정), permission(권한) 반환
   SSR: await (데이터 필수)

2. 쿼리 파라미터로 모드 판별 (?mode=)
   mode=access|list → access 권한 체크
   mode=view        → view 권한 체크
   mode=write       → write 권한 체크
   mode=modify      → modify 권한 체크
   기본값           → access

3. 권한 검증 실패 시:
   SSR:
     게스트 → 302 로그인 (msg=PERMISSION.DENIED.GUEST, redirect=현재URL)
     사용자 → 302 사이트홈 (msg=PERMISSION.DENIED.USER)
     useState("__ssr_403_redirect__")로 1회 제한

   CSR:
     게스트 → showAlert + 로그인 리다이렉트
     사용자 → showAlert + 사이트홈 리다이렉트
```

### 컨텍스트 헤더

모든 렌더 API 호출에 포함:
- `X-Menu-Id` — 현재 메뉴 ID
- `X-Site-Hostname` — 현재 사이트 호스트명

## 06. color-mode — 다크 모드 제한

파일: `middleware/06.color-mode.global.ts`

```
/business/* 또는 /common/login → 다크 모드 허용
그 외 모든 경로              → to.meta.colorMode = "light" (라이트 강제)
```

비동기 작업 없음. 순수 메타데이터 설정.

## SSR/CSR 이중 실행 아키텍처

모든 미들웨어는 SSR(서버)과 CSR(브라우저) 양쪽에서 실행된다.

```
SSR (서버 렌더링):
  요청 → 미들웨어 01~06 → 페이지 컴포넌트 → HTML 문자열 생성
  리다이렉트: HTTP 301/302 (하이드레이션 안전)
  에러: throw createError() (렌더링 중단)

CSR (하이드레이션 후 네비게이션):
  라우트 변경 → 미들웨어 01~06 → 컴포넌트 업데이트
  리다이렉트: navigateTo({ replace: true })
  에러: showAlertMessage + navigateTo
```

### 루프 방지 메커니즘 정리

| 미들웨어 | 방식 | 키 |
|---|---|---|
| 01.site-init | 쿠키 | `__ipBlock` |
| 02.auth | 쿼리 파라미터 + useState | `redirected=1` |
| 03.menu | useState | `__ssr_menu_redirected__` |
| 04.permission | useState + 쿼리 파라미터 | `__ssr_403_redirect__`, `redirected=1` |

`useState`는 SSR 렌더당 1회만 리다이렉트를 허용하여 무한 루프를 방지한다.

## 미들웨어 ↔ 스토어 관계

```
01.site-init    → siteStore.setSite()
01b.layout      → to.meta.layout (스토어 무관)
02.auth         → userStore (isAdmin, isGuest)
03.menu         → menuStore.fetchMenuTree(), setCurrentMenuByPath()
04.permission   → renderStore.fetchRenderData()
06.color-mode   → to.meta.colorMode (스토어 무관)
```
