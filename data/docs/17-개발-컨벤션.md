## API 설계 규칙

### 경로 패턴

```
GET    /back-api/{도메인}           → 목록 (페이징)
GET    /back-api/{도메인}/{idx}     → 단건 조회
POST   /back-api/{도메인}           → 생성
PUT    /back-api/{도메인}/{idx}     → 수정
DELETE /back-api/{도메인}/{idx}     → 삭제
```

### 응답 형식

```java
// 성공
return ResponseEntity.ok(data);

// 페이징
return ResponseEntity.ok(service.search(page, size, keyword));
// → Page<T> 반환 (content, totalElements, totalPages 포함)
```

### 공개 API vs 인증 API

```
공개 (permitAll):
  /back-api/auth/login
  /back-api/auth/logout
  /back-api/render/**
  /back-api/json/**

인증 필요 (authenticated):
  그 외 모든 API
```

## 코드 작성 규칙

### 백엔드

1. **Interface + Impl 분리**: Service는 반드시 인터페이스와 구현체 분리
2. **트랜잭션**: Service 메서드에 `@Transactional` 적용
3. **DTO-Entity 변환**: MapStruct 사용 (`@Mapper(componentModel = "spring")`)
4. **검증**: DTO에 `@NotBlank`, `@Size`, `@Pattern` 등 Bean Validation
5. **QueryDSL**: 복잡한 동적 쿼리에 사용 (단순 CRUD는 JPA Repository)
6. **캐시**: Spring Cache 활용, 변경 시 `@CacheEvict`
7. **AOP**: `@ExecutionTime` (실행 시간 측정), `@SanitizeHtml` (XSS 방지)

### 프론트엔드

1. **SSR 호환**: `process.server` / `import.meta.client` 분기
2. **safeFetch**: 모든 API 호출에 사용 (SSR/CSR 안전)
3. **Provide/Inject**: 게시판 컨텍스트는 Board.vue에서 provide
4. **Pinia Persist**: 필요한 스토어에 persist 옵션 사용
5. **타입 안전**: TypeScript 타입 정의 (types/ 디렉토리)
6. **컴포넌트 분리**: 비즈니스 로직은 composable, UI는 컴포넌트
