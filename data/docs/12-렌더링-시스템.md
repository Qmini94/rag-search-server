# 렌더링 시스템

## 개요

Q-CMS의 페이지 렌더링은 **메뉴 기반 동적 라우팅**으로 작동한다. 캐치올 라우트(`[...slug].vue`)가 모든 경로를 받아서, 메뉴 타입에 따라 게시판 또는 콘텐츠 렌더러를 로드한다.

```
URL 요청 → 미들웨어 체인 → [...slug].vue → 메뉴 타입 분기
                                            ├─ board   → Board.vue → 테마 로드
                                            ├─ content → Content.vue
                                            └─ script  → 직접 페이지 (pages/{site}/...)
```

## 캐치올 라우트 (pages/[...slug].vue)

```vue
<Board v-if="isBoard" :key="componentKey" />
<Content v-else-if="isContent" :key="componentKey" />
```

- `renderStore.data.type`으로 board/content 분기
- `componentKey`로 메뉴 변경 시 컴포넌트 재생성
- 에러 바운더리 + 재시도 버튼 포함

## 게시판 렌더링

### Board.vue (components/render/board/Board.vue)

게시판의 핵심 렌더링 컴포넌트. 모드별로 다른 테마를 로드한다.

```
Board.vue
  ├─ useBoardRenderer() 호출 → BoardCoreContext 생성
  ├─ provide(boardCoreKey, core)  → 하위 컴포넌트에 주입
  ├─ 테마 동적 로드:
  │   boardType + themeName + mode → Loader.vue + Ori.vue
  └─ 모드: list | view | write | modify
```

### useBoardRenderer (핵심 Composable)

게시판 렌더링에 필요한 모든 상태와 동작을 제공한다.

```typescript
const { core, listCtx, gallery, flow } = useBoardRenderer()

// core: BoardCoreContext
boardList, totalPages, totalElements, currentPage  // 목록
viewData, formData, saveArticle, deleteArticle     // 상세/작성
attachments, comments                               // 첨부/댓글
boardOption, fieldDefs, searchableFields            // 설정
mode, isListPage, isViewPage, isWritePage           // 모드
isOwner, canWrite, canModify, canRemove             // 권한
```

### 하위 Composable 구성

```
useBoardRenderer
├── useBoardRoute        쿼리 파라미터 파싱 (mode, idx, page, keyword)
├── useBoardList         목록 데이터 페칭
├── useBoardCrud         CRUD (상세 조회, 저장, 삭제)
├── useBoardComment      댓글 관리
├── useBoardPermission   권한 검사
├── useBoardGallery      갤러리 전용 (선택적)
└── useBoardFlow         진행상태 전용 (선택적)
```

### Provide/Inject 패턴

Board.vue에서 `provide()`로 컨텍스트를 주입하면, 테마 컴포넌트에서 `inject()`로 사용한다.

```
Board.vue (composables/api/render/useBoard.ts에서 import)
  provide(boardCoreKey, core)          → 모든 테마에서 사용
  provide(boardContextKey, core)       → @deprecated (하위 호환)
  provide(boardListKey, listCtx)       → 목록 테마에서 사용
  provide(boardGalleryKey, gallery)    → 갤러리 테마에서 사용
  provide(boardFlowKey, flow)          → 진행상태 테마에서 사용
```

## 테마 시스템

### 디렉토리 구조

```
components/theme/
├── common/              공유 테마 컴포넌트
│   ├── list/            목록 공통 (SearchBox, Pagination, BoardTable)
│   ├── view/            상세 공통 (CommentSection, AttachmentList)
│   ├── write/           작성 공통 (FileUpload, PeriodField)
│   └── flow/            진행상태 공통 (StepProgress)
├── list/                목록형 게시판
│   ├── default/
│   │   ├── metadata.json
│   │   ├── list/  → Loader.vue, Ori.vue
│   │   ├── view/  → Loader.vue, Ori.vue
│   │   └── write/ → Loader.vue, Ori.vue
│   └── qna/       → QnA 변형
├── gallery/             갤러리형 게시판
│   └── default/
│       ├── list/  → Loader.vue, Ori.vue, overrides/
│       ├── view/  → Loader.vue, Ori.vue, overrides/
│       └── write/ → Loader.vue, Ori.vue, overrides/
└── flow/                진행상태형 게시판
    └── default/
        ├── list/  → Loader.vue, Ori.vue
        ├── view/  → Loader.vue, Ori.vue
        └── write/ → Loader.vue, Ori.vue
```

### 테마 파일 규칙

| 파일 | 역할 |
|---|---|
| metadata.json | 테마 메타정보 (Zod 스키마 검증) |
| Loader.vue | 로딩 스켈레톤 UI |
| Ori.vue | 실제 테마 템플릿 |
| overrides/ | 퍼블리싱 HTML 오버라이드 |

### 테마 로딩 경로

```
boardType="LIST.default" → type=list, theme=default
boardType="GALLERY.default" → type=gallery, theme=default

로드 경로: components/theme/{type}/{theme}/{mode}/Ori.vue
```

### 공유 테마 컴포넌트 (theme/common/)

**목록 모드 (list/):**
- SearchBox.vue — 검색 폼 (키워드, 날짜, 타입)

## 콘텐츠 렌더링

Content.vue가 `renderStore.data.value` (parentId)로 콘텐츠를 조회하여 HTML을 렌더링한다.

```
Content.vue
  ├─ useContentRenderer() 호출 (composables/api/render/useContent.ts)
  ├─ GET /back-api/content/{parentId}/view → HTML 본문
  └─ CommonSafeHtml 컴포넌트로 허용 태그/속성 제한 렌더링
```

`CommonSafeHtml`은 허용된 HTML 태그(`div`, `span`, `p`, `table` 등)와 속성(`href`, `src`, `class` 등)만 렌더링한다.

## script 타입 메뉴

slug 캐치올을 우회하여 직접 페이지를 생성한다.

```
메뉴 type="script" → pages/{site}/{pageName}.vue 직접 라우팅
예: /www/half/apply → pages/www/half/apply.vue
```

미들웨어 체인은 동일하게 실행되지만, `[...slug].vue` 대신 직접 페이지가 매칭된다.

## SSR 렌더링 흐름

```
1. 서버 요청
2. 미들웨어 01~06 실행 (SSR)
3. [...slug].vue 매칭
4. Board.vue 또는 Content.vue 로드
5. useBoardRenderer.onServerPrefetch() → 데이터 프리페치
6. 테마 Loader.vue → 스켈레톤
7. Vue SSR → HTML 문자열 생성
8. CSS 버전 + 인라인 스크립트 포함

브라우저 하이드레이션:
9. 미들웨어 01~06 재실행 (CSR)
10. Vue 하이드레이션
11. watch()로 라우트/쿼리 변경 감지 → 재페치
12. Ori.vue 렌더링
```

## 모드 결정

쿼리 파라미터 `?mode=`로 결정:

| 쿼리 | 모드 | 설명 |
|---|---|---|
| (없음) | list | 목록 |
| ?mode=view&idx=1 | view | 상세 보기 |
| ?mode=write | write | 새 글 작성 |
| ?mode=modify&idx=1 | modify | 수정 |

## 권한 레이어링

3단계로 권한을 검사한다:

```
1. 미들웨어 04: 페이지 접근 차단 (access/view/write/modify)
2. renderStore: 모드별 권한 검증
3. 컴포넌트: 버튼 표시/숨김 (canWrite, canModify, canRemove)
```
