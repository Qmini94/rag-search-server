#### npm 실행 오류 해결 (Windows)

Node.js 설치 후 `npm -v`나 `npm install` 실행 시 아래 에러가 발생할 수 있다:

```
npm : 이 시스템에서 스크립트를 실행할 수 없으므로 ...
CategoryInfo : 보안 오류
FullyQualifiedErrorId : UnauthorizedAccess
```

이는 Windows PowerShell의 실행 정책(ExecutionPolicy) 때문이다.

**해결 방법: PowerShell 관리자 모드에서 실행**

1. Windows 검색에서 `PowerShell` 입력
2. **관리자 권한으로 실행** 클릭
3. 아래 명령어 실행:

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

4. `Y` 입력 후 Enter
5. 확인:

```powershell
Get-ExecutionPolicy
# RemoteSigned 가 출력되면 성공
```

이후 일반 터미널(VSCode 터미널, cmd, Git Bash)에서 `npm` 명령어가 정상 동작한다.

> **참고**: `Set-ExecutionPolicy Unrestricted`는 보안상 권장하지 않는다. `RemoteSigned`면 충분하다.

## 인프라 실행 (Docker Compose)

백엔드를 로컬에서 실행하려면 MySQL, Redis가 필요하다. 서버의 docker-compose.yml로 인프라를 실행한다.

```yaml
# docker-compose.yml 주요 서비스
services:
  mysql:     # MySQL 8.0,  port 3306
  redis:     # Redis 7,    port 6379
  gitea:     # Gitea,      port 4000 (→내부 3000)
  jenkins:   # Jenkins,    port 9090 (→내부 8080)
```

```bash
# 서버에서 인프라 실행
docker compose up -d

# 상태 확인
docker ps
```

> 로컬 개발 시 백엔드 없이 프론트엔드만 실행해도 된다. `.env`의 `DEV_PROXY_ORIGIN`으로 운영 서버 API를 프록시한다.

## 일상 작업 흐름

```
1. git pull                    ← 최신 코드 받기
2. npm run dev                 ← 로컬 서버 실행
3. 파일 수정 & 브라우저 확인      ← 작업
4. git add .                   ← 변경 파일 선택
5. git commit -m "작업 내용"     ← 커밋
6. git push                    ← 서버에 업로드
7. Jenkins > Build Now          ← 운영 배포 (필요 시)
```

### 충돌 해결

`git pull` 시 같은 파일의 같은 위치를 서로 다르게 수정하면 충돌이 발생한다.

```
<<<<<<< HEAD
/* 내가 수정한 내용 */
=======
/* 다른 사람이 수정한 내용 */
>>>>>>> origin/main
```

1. `<<<<<<<`, `=======`, `>>>>>>>` 마커를 모두 지우고
2. 최종 원하는 코드만 남긴다
3. `git add .` → `git commit -m "충돌 해결"` → `git push`

> VSCode에서는 충돌 부분에 "현재 변경 사항 수락 / 수신 변경 사항 수락" 버튼이 표시되어 클릭으로 해결 가능

## 주의사항

### 반드시 지킬 것
- 작업 전 `git pull` — 충돌 예방
- 커밋 메시지는 한글로 간결하게 — `메인 배너 여백 조정`
- 작업 끝나면 바로 push

### 절대 하지 말 것
- `.env` 파일 커밋 금지 — 서버 접속 정보 포함
- `node_modules` 커밋 금지 — .gitignore에 포함됨
- `git push --force` 사용 금지 — 다른 사람 작업 덮어쓸 수 있음
