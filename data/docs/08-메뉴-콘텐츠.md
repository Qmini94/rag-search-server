# 메뉴 및 콘텐츠

## 메뉴 시스템 개요

Q-CMS의 메뉴는 **트리 구조**로 관리된다. 최상위에 드라이브(사이트)가 있고, 그 하위에 폴더/게시판/콘텐츠/스크립트/링크 메뉴가 계층적으로 배치된다.

```
drive: "www" (사이트)
├── folder: "소개"
│   ├── content: "인사말" → 콘텐츠 연결
│   └── content: "연혁" → 콘텐츠 연결
├── folder: "게시판"
│   ├── board: "공지사항" → board_notice 테이블
│   └── board: "자유게시판" → board_free 테이블
├── script: "신청" → pages/{site}/apply.vue
└── link: "외부링크" → https://...
```

## Menu 엔티티

테이블: `cms_menu`

| 필드 | 타입 | 설명 |
|---|---|---|
| id | Long (PK) | 메뉴 ID |
| parentId | Long | 부모 메뉴 ID (NULL이면 루트/드라이브) |
| position | int | 형제 간 정렬 순서 |
| level | Long | 트리 깊이 (0: 드라이브) |
| title | String(255) | 표시 이름 |
| name | String(255) | 식별자 (예: "www", "notice") |
| type | String(255) | 메뉴 유형 |
| value | String(255) | 유형별 값 |
| isShow | Boolean | 메뉴 표시 여부 |
| pathUrl | String(255) | URL 경로 |
| pathString | String(255) | 경로 문자열 |
| pathId | String(255) | 점 구분 경로 ID (예: "1.3.8") |

## 메뉴 유형 (type)

| type | 설명 | value 의미 |
|---|---|---|
| drive | 사이트 루트 | - |
| folder | 폴더 (그룹) | - |
| board | 게시판 | boardMasterIdx |
| content | 콘텐츠 | content parentId |
| script | 직접 페이지 | - |
| link | 외부/내부 링크 | URL |

### 메뉴 → 게시판/콘텐츠 연결

- **board 타입**: `value` = BoardMaster의 `idx` → `cms_board_master_menu` 테이블로 연결
- **content 타입**: `value` = Content의 `parentId` → `cms_content_master_menu` 테이블로 연결

```
cms_board_master_menu:
  id, board_master_idx(FK), menu_id(FK), created_date
  UNIQUE: (board_master_idx, menu_id)

cms_content_master_menu:
  id, content_idx(FK), menu_id(FK), created_date
  UNIQUE: (content_idx, menu_id)
```

## pathId 시스템

메뉴 계층을 빠르게 조회하기 위한 점 구분 경로.

```
드라이브 (id=1, pathId="1")
├── 폴더 (id=3, pathId="1.3")
│   ├── 메뉴 (id=8, pathId="1.3.8")
│   └── 메뉴 (id=9, pathId="1.3.9")
└── 폴더 (id=5, pathId="1.5")
```

**활용 쿼리:**
```sql
-- id=3의 모든 자손 조회
SELECT * FROM cms_menu WHERE pathId LIKE '1.3.%'

-- 권한 서비스에서 하위 메뉴 ID 조회
SELECT id FROM cms_menu WHERE pathId LIKE '1.3.%'
```

## 트리 동기화 (MenuSyncProcessor)

관리자 UI에서 트리 전체를 한 번에 저장한다. BFS 기반 동기화 알고리즘.

### 동시성 제어 (MenuSyncLock)

```java
// MenuSyncLock.java
public class MenuSyncLock {
    public static final Object LOCK = new Object();
}
```

`synchronized(MenuSyncLock.LOCK)` 블록으로 메뉴 동기화와 JSON 버전 활성화를 직렬화한다. 단일 JVM 인스턴스 내 동시성 보장.

### SyncContext (내부 상태 레코드)

```
SyncContext:
  rootMenu         : Menu               루트(드라이브) 메뉴
  existingById     : Map<Long, Menu>    기존 메뉴 ID 인덱스
  uniqueKeyMap     : Map<String, Long>  "parentId|type|name" → id 맵
  processedIds     : Set<Long>          처리 완료된 ID
  usedBoardIds     : Set<String>        사용된 게시판 ID (링크 재조정용)
  usedContentIds   : Set<String>        사용된 콘텐츠 ID (링크 재조정용)
  pathCache        : Map<Long, String>  id → pathId 캐시
```

### 동기화 알고리즘 (5 Phase)

```
process(driveName, newTree):
  synchronized(MenuSyncLock.LOCK):

  Phase 1: 기존 상태 로드
    - 루트 메뉴 조회 (driveName)
    - 모든 자손 로드
    - SyncContext 구축 (existingById, uniqueKeyMap)

  Phase 2: 삭제 결정
    - 새 트리의 모든 ID 수집
    - 기존 메뉴 중 새 트리에 없는 것 식별
    - FK 참조 삭제 (boardMasterMenuRepository, contentMasterMenuRepository)
    - 메뉴 삭제

  Phase 3: BFS 처리
    - 레벨별 순회 (Queue 기반)
    - 각 노드:
      - dto.id 존재 → 기존 메뉴 수정
      - dto.id 없음 → 새 메뉴 생성
    - uniqueKey 충돌 검사 (parentId|type|name)
    - 게시판/콘텐츠 value → usedBoardIds/usedContentIds에 수집
    - 일괄 persist (flush)
    - pathId 업데이트: parentPathId + "." + id

  Phase 4: 링크 재조정
    - reconcileAllLinks() 호출
    - 게시판/콘텐츠 연결 테이블 동기화 (upsert + cleanup)
    - isUse 플래그 갱신 (refreshBoardIsUseFlags, refreshContentIsUseFlags)

  Phase 5: 캐시 무효화
    - 처리된 모든 메뉴의 권한 캐시 삭제 (Redis perm:menu:*)
    - 게시판 마스터 캐시 초기화
```

### JSON 파일 내보내기

MenuServiceImpl에서 트리 동기화 후 `JsonFileWriterUtil`로 메뉴 트리를 JSON 파일로 내보낸다. 프론트엔드 SSR에서 직접 읽어 사용.

## 메뉴 API

```
GET  /back-api/menu/drive           → 루트 메뉴(드라이브) 목록
GET  /back-api/menu/{name}/lite     → 경량 트리 (관리자 사이드바용)
GET  /back-api/menu/{name}/tree     → 전체 트리 (관리자 메뉴 관리용)
```

### 응답 DTO

**MenuTreeLiteResponse** (경량):
```
id, parentId, title, name, type, value, level, isShow, pathUrl, pathId
children: List<MenuTreeLiteResponse>
```

**MenuTreeResponse** (전체):
```
id, parentId, position, level, title, name, type, value,
isShow, pathUrl, pathString, pathId
children: List<MenuTreeResponse>
```

## Content 엔티티

테이블: `cms_content`

| 필드 | 타입 | 설명 |
|---|---|---|
| idx | Long (PK) | 콘텐츠 ID |
| parentId | Long | 그룹 부모 ID (루트는 parentId=idx) |
| isUse | Boolean | 메뉴 연결 활성 여부 |
| isMain | Boolean | 현재 공개 버전 여부 |
| isDraft | Boolean | 임시저장 여부 |
| title | String(200) | 제목 |
| content | LONGTEXT | HTML 본문 |
| hostname | String(30) | 사이트 호스트명 필터 |
| createdBy | String(30) | 생성자 |
| updatedBy | String(30) | 수정자 |

## 콘텐츠 버전 관리

하나의 콘텐츠 그룹은 `parentId`로 묶인다. 여러 버전 중 `isMain=true`인 것이 공개 버전.

```
콘텐츠 그룹 (parentId=10):
  ├─ idx=10, isMain=true  ← 현재 공개 버전
  ├─ idx=15, isMain=false ← 이전 버전
  └─ idx=20, isMain=false ← 이전 버전

버전 전환: activeContent(idx=15)
  → idx=10.isMain=false
  → idx=15.isMain=true
```

### 임시저장 (Draft) 흐름

```
1. createDraft(hostname)         → 빈 Content 생성 (isDraft=true), parentId 반환
2. 파일 업로드 (parentId 참조)    → 파일을 Content에 연결
3. publishDraft(parentId, req)   → isDraft=false, isMain=true, 제목/본문 설정
   또는
   deleteDraft(parentId)         → 드래프트 + 관련 파일 삭제
```

## 콘텐츠 API

```
GET    /back-api/content                  → 목록 (페이징, 검색)
GET    /back-api/content/group/{idx}      → 그룹 전체 버전 조회
GET    /back-api/content/{idx}/view       → 공개 버전 조회 (isMain=true)

POST   /back-api/content/draft?hostname=  → 임시저장 생성
PUT    /back-api/content/draft/{parentId} → 임시저장 → 공개
DELETE /back-api/content/draft/{parentId} → 임시저장 취소

POST   /back-api/content                  → 루트 콘텐츠 생성
POST   /back-api/content/{idx}            → 버전 추가
PUT    /back-api/content/{idx}            → 수정
PUT    /back-api/content/{idx}/active     → 공개 버전 전환
DELETE /back-api/content/{idx}            → 단건 삭제
DELETE /back-api/content/group/{idx}      → 그룹 전체 삭제
```

## 렌더링 데이터 (RenderService)

프론트엔드가 메뉴 페이지를 렌더링할 때 필요한 데이터를 조회한다.

```
GET /back-api/render (공개 API)
  │
  ├─ JWT에서 menuId 추출
  ├─ MenuService.getMenuRenderById(menuId) → type, value, name
  ├─ PermissionService.getPermissionByMenu() → 권한 정보
  │
  ├─ type별 분기:
  │   ├─ "board"   → BoardMasterResponse 로드 (옵션 포함)
  │   └─ 그 외     → option = null
  │
  └─ 반환: RenderResponse { type, value, option, permission }
```

### RenderResponse

```json
{
  "type": "board",
  "value": "5",
  "option": {
    "idx": 5,
    "boardId": "notice",
    "boardName": "공지사항",
    "boardType": "LIST.default",
    "isAdminReply": true,
    "isPrivate": false,
    ...
  },
  "permission": {
    "view": true,
    "write": true,
    "modify": false,
    "remove": false,
    "manage": false
  }
}
```

## 링크 재조정 (reconcileAllLinks)

메뉴 트리 동기화 후, 게시판/콘텐츠 연결을 자동으로 정리한다.

```
reconcileAllLinks():
  1. upsertBoardLinksFull      → type="board"인 메뉴의 연결 생성
  2. cleanupBoardLinksFull     → 불필요한 연결 제거
  3. upsertContentLinksFull    → type="content"인 메뉴의 연결 생성
  4. cleanupContentLinksFull   → 불필요한 연결 제거
  5. refreshBoardIsUseFlagsFull    → 게시판 isUse 동기화
  6. refreshContentIsUseFlagsFull  → 콘텐츠 isUse 동기화
```
