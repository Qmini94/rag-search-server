# 게시판 시스템

## 아키텍처 개요

Q-CMS의 게시판은 **동적 테이블 기반**이다. 관리자가 게시판을 생성하면 물리 테이블(`board_{boardId}`)이 DDL로 자동 생성된다. 관심사가 4개 레이어로 분리되어 있다.

```
BoardMasterService   — 게시판 설정 CRUD (마스터 + 필드 정의)
DynamicBoardService  — 게시글 런타임 CRUD (옵션 프로세서 포함)
BoardSchemaDao       — DDL만 (CREATE/ALTER/DROP TABLE)
DynamicBoardDao      — DML만 (INSERT/UPDATE/SELECT/DELETE)
```

## 메뉴 → 게시판 연결

```
menuId → cms_menu (type="board", value=boardMasterIdx)
  → cms_board_master (boardId)
  → board_{boardId} 물리 테이블
```

`DynamicBoardDaoImpl.resolveBoardIdByMenuId()`: cms_menu과 cms_board_master를 JOIN하여 boardId를 해석한다.

## 필드 시스템

### 고정 필드 (FIXED) — 19개

모든 게시판 공통. ALTER TABLE로 변경/삭제 불가.

```
idx, menu_id, reg_id, reg_name, reg_pin, reg_ip, depart_name,
created_date, updated_date, is_deleted, title, content, view_count,
is_approved, admin_comment, admin_comment_date, is_private_post,
period_start, period_end
```

### 프리셋 필드 — BoardType별

| 타입 | 추가 필드 |
|---|---|
| LIST | is_top_fixed, top_start, top_end, pidx, level, seq |
| GALLERY | mainimage_idx, is_top_fixed, top_start, top_end |
| FLOW | process_1 |

### 커스텀 필드 (MUTABLE)

`cms_board_field_definition` 테이블에 저장. 관리자가 자유롭게 추가/수정/삭제.

| 속성 | 설명 |
|---|---|
| fieldName | DB 컬럼명 (`^[a-zA-Z][a-zA-Z0-9_]*$`) |
| fieldType | SQL 타입 (VARCHAR, TEXT, INT, DATE, DATETIME, BOOLEAN) |
| isRequired | NOT NULL 제약 |
| isSearchable | 검색 필터에 포함 |
| isEncrypted | 암호화 저장 → VARCHAR(1024)로 변환 |
| fieldOrder | 표시 순서 |

## DDL 생성 (BoardSchemaDaoImpl)

### 테이블 생성

```
createBoardTable(masterIdx, boardId):
  1. MySQL GET_LOCK("board:ddl:{boardId}", 10초) 획득
  2. BoardType 프리셋 필드 로드
  3. cms_board_field_definition에서 커스텀 필드 로드
  4. 이름 충돌 검증 (프리셋 vs 커스텀)
  5. CREATE TABLE board_{boardId}:
     - idx BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT
     - 고정 필드 (19개)
     - 프리셋 필드 (타입별)
     - 커스텀 필드
     - TABLE COMMENT: "owner=board_id:{boardId};masterIdx:{masterIdx}"
  6. 기본 인덱스: (is_deleted, created_date), (created_date)
  7. 프리셋 indexHint 컬럼 인덱스 추가
  8. RELEASE_LOCK
```

### 스키마 동기화 (ALTER TABLE)

```
syncPhysicalTableWithDefinitions(masterIdx):
  1. information_schema에서 현재 물리 컬럼 조회
  2. 목표 필드 정의 로드
  3. MUTABLE 필드에 대해:
     ADD   : 정의에 있고 테이블에 없는 경우
     MODIFY: 타입/null/default가 다른 경우
     DROP  : 테이블에 있고 정의에 없는 경우 (FIXED 제외)
  4. 안전 가드:
     - FIXED 필드는 절대 DROP/MODIFY 안 함
     - NOT NULL without DEFAULT 방지
     - VARCHAR 길이 축소 방지
```

### 동시성 제어

MySQL `GET_LOCK("board:ddl:{boardId}", 10)` / `RELEASE_LOCK` 사용. 같은 게시판에 대한 DDL은 직렬 실행.

### 보상 트랜잭션 (BoardMasterServiceImpl)

```
createBoard 실패 시:
  → BoardMaster 삭제 → FieldDefinition 삭제 → safeDropOwned(테이블)

updateBoard 실패 시:
  → 스냅샷에서 이전 FieldDefinition 복원 → syncPhysicalTable 재실행

deleteBoard 실패 시:
  → 스냅샷에서 Master + Fields 복원
```

`safeDropOwned()`: TABLE_COMMENT의 `owner=board_id:X;masterIdx:Y` 메타데이터로 소유권 확인 후 DROP.

## 게시글 CRUD (DynamicBoardServiceImpl)

### 옵션 프로세서 체인 (전략 패턴)

7개 프로세서가 고정 순서로 실행된다:

```java
private static final List<BoardOptionProcessor> PROCESSORS = List.of(
    new AuthorOnlyProcessor(),      // F: 본인 글만 보기
    new AdminApprovalProcessor(),   // K: 관리자 승인제
    new PrivatePostProcessor(),     // C: 비공개 글
    new PeriodProcessor(),          // D: 게시 기간
    new TopFixedProcessor(),        // E: 상단 고정
    new MaskAuthorProcessor(),      // G: 작성자 마스킹
    new ThreadReplyProcessor()      // B: 답글 스레드
);
```

### BoardOptionProcessor 인터페이스

```java
public interface BoardOptionProcessor {
    boolean isEnabled(BoardOptionContext ctx);       // 옵션 활성 여부
    default boolean shouldDeny(Map row, ctx);        // 접근 거부 (true → 예외)
    default void transformRow(Map row, ctx);         // 행 데이터 변환
    default String beforeSave(Map data, ctx);        // 저장 전 검증/변환
}
```

### BoardOptionContext (공유 컨텍스트)

```java
// 프로세서에 필요한 모든 정보
boardOpt  : Map<String, Object>    // 게시판 옵션 플래그 (getBoardOptionByMenuId)
user      : JwtAuthenticatedUser   // 현재 사용자
manager   : boolean                // MANAGE 권한 보유 여부
menuId    : Long                   // 현재 메뉴
dao       : DynamicBoardDao        // DB 조회용

// 유틸리티 메서드
static boolean toBool(Object v)          // DB값 → boolean (Integer 0/1, Boolean)
static boolean isAuthor(Map row, user)   // reg_id == userId?
static String maskName(String name)      // "홍길동" → "홍OO"
static String objectToDateStr(Object v)  // YYYY-MM-DD 추출
```

### 각 프로세서 상세

**AuthorOnlyProcessor (F)**
- `shouldDeny()`: 관리자/매니저/작성자가 아니면 접근 거부

**AdminApprovalProcessor (K)**
- `shouldDeny()`: 미승인 글에 관리자/매니저/작성자가 아니면 접근 거부
- `beforeSave()`: 관리자/매니저 → `is_approved=1`, 일반 사용자 → `is_approved=0`

**PrivatePostProcessor (C)**
- `shouldDeny()`: 비공개 글에 관리자/매니저/작성자가 아니면 접근 거부
- `transformRow()`: 비공개 글의 제목을 "비공개 글입니다."로, 내용을 빈 문자열로 마스킹

**PeriodProcessor (D)**
- `shouldDeny()`: 기간 외 글에 관리자/매니저/작성자가 아니면 접근 거부
  - periodEnd 미설정 → 거부
  - 오늘 > periodEnd → 거부
  - 오늘 < periodStart → 거부
- `transformRow()`: 기간 외 상단고정 해제 (기간 > 상단고정 우선순위)

**TopFixedProcessor (E)**
- `transformRow()`: topEnd가 지난 상단고정 해제

**MaskAuthorProcessor (G)**
- `transformRow()`: 관리자/매니저/작성자가 아니면 reg_name을 마스킹 ("홍길동" → "홍OO")

**ThreadReplyProcessor (B)**
- `beforeSave()`:
  - 답글 (pidx ≠ 0): 관리자/매니저만 작성 가능, level = 부모.level + 1, seq = 기존 답글 수 + 1
  - 원글 (pidx = 0): pidx/level/seq = "0"

### 목록 조회 흐름 (getList)

```
1. 필드 정의 로드 (프리셋 + 커스텀 병합)
   DynamicBoardDaoImpl.getFieldDefinitionsByMenuId()
   → DB 필드 우선, 프리셋 필드 보충 (이름 충돌 시 DB 우선)

2. BoardAccessContext 생성
   → userId, admin, manager, authorOnly, usePeriod, adminApproval, topFixed, threadReply

3. DynamicBoardSqlBuilder.buildPaginatedListQuery()
   WHERE: is_deleted=false, menu_id={menuId}
   + 키워드 검색 (isSearchable=true 필드, 암호화 필드 제외)
   + 날짜 범위 필터
   + 접근 제어 필터 (authorOnly, adminApproval, usePeriod, topFixed)
   + 스레드 답글 정렬 (pidx/seq 서브쿼리)
   + 상단고정 우선 정렬: is_top_fixed DESC, created_date DESC
   + 정렬 필드 화이트리스트 검증

4. 암호화 필드 복호화 (CryptoUtil)

5. 옵션 프로세서 7개 순차 적용
   각 행에 대해: isEnabled → shouldDeny → transformRow

6. 첨부파일 로드

7. snake_case → camelCase 변환
```

### 상세 조회 흐름 (getOne)

```
1. selectOneByMenuId로 게시글 조회
2. 조회수 증가 (Redis 세션 기반 중복 방지)
   키: view:{boardId}:{postIdx}:{sessionKey}, TTL: 24시간
3. 암호화 필드 복호화
4. 옵션 프로세서: shouldDeny 체크 (접근 거부 시 예외)
5. 옵션 프로세서: transformRow (마스킹 등)
6. 첨부파일 + 이전/다음 글 로드
```

### 저장 흐름 (save)

```
1. 필드 정의 + 옵션 로드
2. 옵션 프로세서 beforeSave() 실행
   - AdminApproval: is_approved 설정
   - ThreadReply: pidx/level/seq 설정
3. 시스템 필드 자동 설정
   - created_date, updated_date = NOW() (KST)
   - reg_id, reg_name, reg_pin, reg_ip (JWT에서)
   - depart_name (사용자 정보)
4. XSS 이스케이프 (시스템 필드 제외)
5. 암호화 필드 암호화 (CryptoUtil)
6. DynamicBoardSqlBuilder로 INSERT/UPDATE SQL 생성
7. JDBC 실행
```

### 2중 접근 제어

```
SQL 레벨 (BoardAccessContext → WHERE 절):
  - authorOnly: reg_id = :userId OR 관리자
  - adminApproval: is_approved = 1 OR 작성자 OR 관리자
  - usePeriod: period_start/end 범위 내 OR 관리자
  - topFixed: 상단고정 기간 필터

행 레벨 (옵션 프로세서 → shouldDeny/transformRow):
  - 개별 행에 대한 세밀한 접근 제어
  - 제목/내용 마스킹, 작성자명 마스킹
```
