```
#wrap.main

├── WwwCommonQuickArea          ← 우측 퀵 플로팅 영역 (신청, 업로드, TOP)

    ├── .main_tour              ← 장흥 힐링여행 섹션
```

### CSS 로드 순서 (useVersionedCss)

`www-main.vue`의 `useHead` 블록에서 다음 순서로 CSS를 주입한다.

```ts
useHead({
  link: useVersionedCss([
    "/public/style/www/plugin/swiper-8.4.7.min.css", // Swiper 플러그인 (반드시 가장 먼저)
    "/public/style/www/common/base.css",             // 공통 기초 스타일
    "/public/style/www/module/component.css",        // 공통 컴포넌트 스타일
    "/public/style/www/module/codingmap.css",        // 아이콘/코딩맵
    "/public/style/www/halftour/layout.css",         // 메인 레이아웃
    "/public/style/www/halftour/main.css",           // 메인 전용 스타일
  ]),
});
```

`useVersionedCss`는 정적 CSS 파일에 캐시 버스팅 쿼리스트링(`?v={version}`)을 자동으로 붙여준다.

- SSR 시: 서버 미들웨어(`server/middleware/css-version.ts`)가 주입한 동적 버전을 `ssrContext.event.context.cssVersion`에서 읽는다.
- CSR 시: SSR이 `useState("cssVersion")`에 저장해둔 값을 재사용한다 (hydration 불일치 방지).
- 파일 위치: `composables/useVersionedCss.ts`

## 2. 게시판 데이터 연결

### CommunityTab.vue — menuId 하드코딩 방식

`components/www/main/CommunityTab.vue`는 공지사항과 자주하는질문 탭을 보여준다.

```ts
// components/www/main/CommunityTab.vue
const MENU = {
  notice: 124,  // 공지사항 menuId
  ask: 131,     // 자주하는질문 menuId
};
```

- 두 menuId는 관리자 메뉴 관리에서 확인한 실제 DB 값이다.
- `menuStore.findRoutePath(menuId)`로 "더보기" 링크 URL을 동적으로 생성한다.
- `linkToList: true` 옵션을 쓰면 각 아이템 URL이 상세보기가 아닌 목록 페이지로 이동한다 (자주하는질문 탭에 적용).
- 탭 전환은 `activeIndex` ref로 관리하며, 탭 클릭 시 해당 인덱스의 `display` 속성만 토글한다. 데이터는 모든 탭이 마운트 시 동시에 로드된다.

```html
<!-- 탭 구조 핵심 -->
<div v-for="(tab, idx) in tabs" :class="['tab_box', activeIndex === idx && 'on']">
  <CommonWidgetList
    :menu-id="tab.menuId"
    :size="3"
    :item-template="tplCommunity"
    :link-to-list="tab.linkToList"
    wrapper-tag="ul"
    wrapper-class="list"
  />
</div>
```

아이템 템플릿 문자열(`tplCommunity`)은 `{%url}`, `{%day}`, `{%month}`, `{%title}`, `{%desc}` 플레이스홀더를 사용한다.

### CommonWidgetList.vue — safeFetch와 menuOverride 패턴

`components/common/WidgetList.vue`는 게시판 목록을 메인에서 위젯 형태로 렌더링하는 범용 컴포넌트다.

```ts
// onMounted 내부 핵심 로직
const res = await safeFetch<any>("/board", {
  query: { page: 0, size: props.size, sort: "regDate,desc" },
  credentials: "include",
  timeout: props.timeout ?? 2000,
  defaultValue: { code: 500, message: "게시판 목록 조회 실패", data: {} },
  menuOverride: { id: props.menuId, site: siteStore.site }, // 핵심: 어떤 게시판을 볼지 지정
  cacheScope: "url+menu",
});
```

`menuOverride` 패턴이 핵심이다. `/board` API는 현재 라우트의 menuId를 보는 것이 기본이지만, `menuOverride: { id: props.menuId, site: ... }`를 넘기면 지정한 menuId의 게시판 데이터를 가져온다. 메인 페이지처럼 URL 라우트와 무관하게 특정 게시판 데이터를 렌더링할 때 필수적이다.

응답 데이터는 여러 구조를 허용한다:
- 배열 직접 반환
- `res.data` 배열
- `res.data.items` 배열
- `res.data.content` 배열 (Spring Page 응답)

날짜는 자동으로 `YYYY.MM.DD` 포맷으로 변환되며, 등록 후 7일 이내면 `{%isNew}` / `{%newBadge}` 플레이스홀더를 쓸 수 있다.

### 새 게시판을 메인에 추가하는 방법 (step by step)

1. **관리자에서 menuId 확인**: 관리자 > 메뉴 관리에서 추가할 게시판의 menuId(숫자)를 확인한다.

2. **CommunityTab.vue의 MENU 상수에 추가** (탭 형식으로 추가할 경우):
   ```ts
   const MENU = {
     notice: 124,
     ask: 131,
     news: 150,  // 추가
   };
   ```

3. **tabs 배열에 항목 추가**:
   ```ts
   const tabs = computed(() => [
     { label: "공지사항", menuId: MENU.notice, moreUrl: menuStore.findRoutePath(MENU.notice) },
     { label: "자주하는질문", menuId: MENU.ask, moreUrl: menuStore.findRoutePath(MENU.ask), linkToList: true },
     { label: "새소식", menuId: MENU.news, moreUrl: menuStore.findRoutePath(MENU.news) }, // 추가
   ]);
   ```

4. **탭 형식이 아닌 독립 섹션으로 추가할 경우**: `www-main.vue`에 새 `<div>` 섹션을 추가하고 `<CommonWidgetList>`를 직접 사용한다:
   ```html
   <div class="main_news">
     <div class="inner">
       <CommonWidgetList
         :menu-id="150"
         :size="5"
         :item-template="tplNews"
         wrapper-tag="ul"
         wrapper-class="news_list"
       />
     </div>
   </div>
   ```

5. **CSS 추가**: `main.css`에 새 섹션 스타일을 작성한다. Tailwind 클래스는 사용 불가 (아래 5절 참조).

## 3. Swiper 사용 가이드

### Vue 컴포넌트 방식 — TourBanner.vue

Nuxt 환경에서 권장되는 방식이다. `swiper/vue`의 `<Swiper>`, `<SwiperSlide>` 컴포넌트를 사용한다.

```ts
// components/www/main/TourBanner.vue
import { Swiper, SwiperSlide } from "swiper/vue";
import {
  Navigation as SwiperNavigation,
  Pagination as SwiperPagination,
  Autoplay as SwiperAutoplay,
} from "swiper/modules";
import type { Swiper as SwiperType } from "swiper";

// navigation/pagination의 DOM 요소는 ref로 직접 바인딩
const prevRef = ref<HTMLElement | null>(null);
const nextRef = ref<HTMLElement | null>(null);
const paginationRef = ref<HTMLElement | null>(null);

// 인스턴스 저장 (정지/재생 제어용)
let swiperInstance: SwiperType | null = null;
const onSwiper = (swiper: SwiperType) => { swiperInstance = swiper; };
```

```html
<Swiper
  :modules="[SwiperAutoplay, SwiperNavigation, SwiperPagination]"
  :autoplay="{ delay: 3000, disableOnInteraction: false }"
  :speed="300"
  :loop="true"
  :observer="true"
  :observe-parents="true"
  :navigation="{ prevEl: prevRef, nextEl: nextRef }"
  :pagination="{ el: paginationRef, type: 'fraction' }"
  @swiper="onSwiper"
>
  <SwiperSlide v-for="img in items" :key="img.idx">...</SwiperSlide>
</Swiper>

<!-- navigation 버튼: ref로 연결 -->
<button ref="prevRef" class="btn_prev">이전</button>
<button ref="nextRef" class="btn_next">다음</button>
<p ref="paginationRef" class="page_num"></p>
```

정지/재생 제어:
```ts
const togglePause = () => {
  if (!swiperInstance) return;
  if (isPaused.value) {
    swiperInstance.autoplay.start();
    isPaused.value = false;
  } else {
    swiperInstance.autoplay.stop();
    isPaused.value = true;
  }
};
```

### Vanilla JS 방식 — gallery/default/list/Ori.vue (이중 Swiper + Thumbs 연동)

갤러리 모달처럼 동적으로 DOM이 생성된 후 Swiper를 초기화해야 할 때는 `SwiperCore`를 직접 new로 생성한다.

```ts
import SwiperCore from "swiper";
import { Thumbs } from "swiper/modules";

const swiperTopEl = ref<HTMLElement | null>(null);
const swiperBotEl = ref<HTMLElement | null>(null);
let swiperTop: SwiperCore | null = null;
let swiperBot: SwiperCore | null = null;

const initSwipers = () => {
  if (!swiperTopEl.value || !swiperBotEl.value) return;

  // 반드시 하단(썸네일) Swiper를 먼저 생성
  swiperBot = new SwiperCore(swiperBotEl.value, {
    slidesPerView: "auto",
    spaceBetween: 10,
    watchSlidesProgress: true,  // Thumbs 연동에 필수
  });

  // 이후 상단 Swiper 생성 시 thumbs에 swiperBot 연결
  swiperTop = new SwiperCore(swiperTopEl.value, {
    modules: [Thumbs],
    spaceBetween: 10,
    thumbs: { swiper: swiperBot },
  });
};

// 모달 닫을 때 반드시 destroy
const closeModal = () => {
  swiperTop?.destroy(true, true);
  swiperBot?.destroy(true, true);
  swiperTop = null;
  swiperBot = null;
};
```

HTML 구조:
```html
<!-- 메인 Swiper -->
<div ref="swiperTopEl" class="swiper swiper_gallery_top">
  <div class="swiper-wrapper">
    <div v-for="img in modalImages" class="swiper-slide">...</div>
  </div>
</div>

<!-- 썸네일 Swiper -->
<div ref="swiperBotEl" class="swiper swiper_gallery_bot">
  <div class="swiper-wrapper">
    <div v-for="img in modalImages" class="swiper-slide">...</div>
  </div>
</div>
```

### Swiper CSS 로드

Swiper CSS는 npm 패키지에서 import하지 않고 정적 파일로 관리한다.

```
public/style/www/plugin/swiper-8.4.7.min.css
```

`www-main.vue`의 `useVersionedCss` 배열에 반드시 가장 먼저 추가해야 한다. 순서가 틀리면 Swiper 기본 스타일이 프로젝트 CSS에 덮여버린다.

### 여러 Swiper 인스턴스 동시 사용 시 주의점

- **ref 분리 필수**: 각 Swiper마다 별도의 `ref` 변수를 선언한다. 같은 ref를 재사용하면 두 번째 Swiper가 첫 번째를 덮어쓴다.
- **destroy 필수**: 모달 닫기, 컴포넌트 unmount 시 `swiper.destroy(true, true)`를 호출한다. 첫 번째 인수는 완전 초기화, 두 번째는 CSS 클래스 제거 여부다. 누락 시 메모리 누수 및 DOM 잔여 이벤트 문제가 발생한다.
- **Thumbs 연동 순서**: 썸네일 Swiper를 반드시 먼저 생성한 뒤, 메인 Swiper의 `thumbs.swiper`에 참조를 전달한다.
- **nextTick 대기**: `v-if`로 DOM을 조건부 렌더링한 후 Swiper를 초기화할 때는 `await nextTick()` 후에 `initSwipers()`를 호출해야 한다.

### 새 Swiper 섹션 추가하는 방법

1. `www-main.vue`의 `useVersionedCss` 배열에 `swiper-8.4.7.min.css`가 이미 있는지 확인 (중복 추가 불필요).
2. 새 컴포넌트 파일 생성 (예: `components/www/main/NewBanner.vue`).
3. Vue 컴포넌트 방식이면 `swiper/vue`에서 import, Vanilla JS 방식이면 `swiper`에서 `SwiperCore` import.
4. navigation/pagination용 DOM ref를 컴포넌트마다 독립 선언.
5. `www-main.vue`에 새 섹션 div를 추가하고 컴포넌트 태그를 배치.

## 4. 비주얼 배너/팝업 연동

### CommonVisualBanner — 슬롯 기반 래퍼

`components/common/VisualBanner.vue`는 데이터 페칭을 담당하는 헤드리스 래퍼 컴포넌트다. 실제 UI 렌더링은 부모 컴포넌트가 `v-slot`으로 구현한다.

```html
<!-- 사용 예시 -->
<CommonVisualBanner v-slot="{ items, currentIndex, total, next, prev, togglePause, isPaused }" :popup-id="22">
  <!-- items: VisualBannerItem[] -->
  <!-- 여기서 원하는 UI를 자유롭게 구현 -->
</CommonVisualBanner>
```

슬롯으로 노출되는 값:

| 슬롯 변수 | 타입 | 설명 |
|---|---|---|
| `items` | `VisualBannerItem[]` | 이미지 목록 (sortOrder 정렬) |
| `currentIndex` | `Ref<number>` | 현재 슬라이드 인덱스 |
| `prevIndex` | `Ref<number>` | 이전 슬라이드 인덱스 (CSS 트랜지션용) |
| `current` | `VisualBannerItem \| null` | 현재 슬라이드 아이템 |
| `total` | `ComputedRef<number>` | 전체 슬라이드 수 |
| `effectClass` | `ComputedRef<string>` | `vis_slider--fade` 등 CSS 효과 클래스 |
| `next` / `prev` | `() => void` | 슬라이드 이동 |
| `goTo` | `(index: number) => void` | 특정 슬라이드로 이동 |
| `togglePause` / `isPaused` | 함수 / `Ref<boolean>` | 자동재생 정지/재생 |

### VisualPopup.vue — 커스텀 슬라이드 UI

`components/www/main/VisualPopup.vue`는 `CommonVisualBanner`를 이용해 직접 슬라이드 로직(on/out CSS 클래스 전환)을 구현한 예시다. Swiper 없이 CSS 트랜지션만으로 동작한다.

```html
<div class="vis_slide"
  :class="{ on: i === currentIndex, out: i === prevIndex }"
>
```

### TourBanner.vue — Swiper와 CommonVisualBanner 조합

`TourBanner.vue`는 `CommonVisualBanner`로 데이터를 받아 Swiper로 렌더링하는 조합 패턴이다.

```html
<CommonVisualBanner v-slot="{ items }" :popup-id="popupId">
  <Swiper ...>
    <SwiperSlide v-for="img in items" :key="img.idx">...</SwiperSlide>
  </Swiper>
</CommonVisualBanner>
```

### useVisualBanner composable

`composables/api/render/useVisualBanner.ts`가 실제 API 호출을 담당한다.

```ts
export async function useVisualBanner(popupIdx: number | Ref<number>): Promise<UseVisualBannerReturn>
```

- API 엔드포인트: `GET /popup/{idx}/active-images`
- SSR + CSR 모두 지원 (`useAsyncData` 사용, timeout 5000ms)
- 자동재생 간격(`slideInterval`), 효과(`slideEffect`), 자동재생 여부(`autoSlide`)는 모두 API 응답에서 가져온다 (관리자에서 설정).
- `items`는 API 응답의 `data.images` 배열을 `sortOrder` 기준으로 정렬한 결과다.

### popupId와 관리자 팝업 관리의 연결

`popupId`는 관리자 > 홈페이지 관리 > 팝업 관리에서 생성한 팝업의 DB idx 값이다.

```ts
// www-main.vue
const BANNER = {
  mainTour: 22,  // 관리자 팝업 관리의 idx=22인 팝업
};

// 레이아웃 템플릿에서 컴포넌트에 전달
<WwwMainTourBanner :popup-id="BANNER.mainTour" />
```

새 비주얼 배너 섹션을 추가할 때:
1. 관리자 > 팝업 관리에서 새 팝업을 생성하고 이미지를 등록한다.
2. 생성된 팝업의 idx를 확인한다.
3. `www-main.vue`의 `BANNER` 상수에 추가한다.
4. 해당 idx를 `:popup-id`로 넘기는 컴포넌트를 작성한다.

### Tailwind 사용 불가

**www 사이트는 전통 CSS만 사용한다.** Tailwind 유틸리티 클래스(`flex`, `text-lg`, `mt-4` 등)를 템플릿에 작성하면 빌드 결과에 해당 스타일이 포함되지 않는다.

- 스타일은 반드시 `public/style/www/` 하위의 CSS 파일에 직접 작성한다.
- `www-main.vue`의 `useVersionedCss`에 등록된 파일만 메인 페이지에 로드된다.
- 신규 CSS 파일을 추가하면 반드시 `useVersionedCss` 배열에 추가해야 한다.
- Element Plus 컴포넌트도 사용하지 않는다 (관리자 페이지 전용).
