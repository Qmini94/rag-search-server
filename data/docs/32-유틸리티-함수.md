## 1. API 통신

### safeFetch

**파일**: `utils/safeFetch.ts`

SSR/CSR 겸용 안전 API 호출 래퍼. 모든 백엔드 API 호출은 이 함수를 통해 수행한다.

#### 시그니처

```typescript
export async function safeFetch<T = any>(
  url: string,
  options: SafeFetchOptions = {}
): Promise<T>
```

#### SafeFetchOptions 파라미터

| 옵션 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `timeout` | `number` | `2000` | AbortController 타임아웃 (ms) |
| `defaultValue` | `any` | `null` | 실패 시 반환할 기본값 |
| `throwOnFail` | `boolean` | `false` | true이면 실패 시 throw, false이면 defaultValue 반환 |
| `headers` | `HeadersInit` | `{}` | 추가 요청 헤더 |
| `credentials` | `RequestCredentials` | — | fetch credentials 옵션 (CSR 전용) |
| `method` | `"GET"\|"POST"\|"PUT"\|"DELETE"\|"PATCH"` | `"GET"` | HTTP 메서드 |
| `body` | `any` | — | 요청 본문 (객체 전달 시 자동 JSON 직렬화) |
| `query` | `Record<string, any>` | — | URL 쿼리 파라미터 (자동으로 URLSearchParams 변환) |
| `signal` | `AbortSignal` | — | 외부 AbortSignal 연결 |
| `menuOverride` | `MenuOverride` | — | 이 요청에서만 X-Menu-Id / X-Site-Hostname 헤더를 교체 |
| `cacheScope` | `"url"\|"url+menu"` | `"url"` | CSR 중복요청 캐시 키 범위 |

#### MenuOverride 타입

```typescript
type MenuOverride = {
  id?: string | number;   // 이 호출에서만 사용할 메뉴 ID
  site?: string;          // 이 호출에서만 사용할 사이트 호스트명
  strategy?: "override" | "fallback";
  // override(기본): menuOverride 값이 store 값을 무조건 대체
  // fallback: store에 값이 없을 때만 menuOverride 값 적용
};
```

#### 반환값

`Promise<T>` — 서버 응답 JSON을 그대로 반환한다. 서버 규약 `{ code, message, data }` 구조도 그대로 전달된다 (code === 200이 성공).

#### 동작 규칙

- **SSR**: `runtimeConfig.apiBase` (내부 주소) 사용 + 원 요청의 `cookie`, `user-agent`, `accept-language`만 포워딩
- **CSR**: `runtimeConfig.public.apiBase` 사용
- **중복 요청 캐시**: CSR에서만 동일 캐시 키의 요청을 하나의 Promise로 병합
- **401/403 처리**: `isGuest` 여부에 따라 로그인 페이지 이동 또는 이전 페이지 복귀를 단일 처리 (1.5초 내 중복 호출 방지)
- **4030(서버 규약 코드) 처리**: HTTP 2xx 응답이지만 `json.code`가 401/403인 경우에도 동일한 인증 오류 처리 수행
- **세션 만료 타이머**: 응답 헤더 `X-Session-Expires` 또는 쿠키 `sessionExpires`로 자동 로그아웃 타이머 갱신
- **본문 자동 처리**: 일반 객체 → JSON 직렬화 + `Content-Type: application/json` 자동 부여, FormData → Content-Type 헤더 제거(브라우저 자동 처리)

#### 사용 예시

```typescript
// 기본 GET
const res = await safeFetch<{ code: number; data: BoardList }>('/api/board/list')

// POST + body
const res = await safeFetch('/api/board/write', {
  method: 'POST',
  body: { title: '제목', content: '내용' },
  throwOnFail: true,
})

// 메뉴 헤더 일시 교체 (다른 메뉴의 데이터 조회)
const res = await safeFetch('/api/board/list', {
  menuOverride: { id: 42, site: 'jh' },
  cacheScope: 'url+menu',
})

// 타임아웃 연장 + 기본값 지정
const res = await safeFetch('/api/slow-endpoint', {
  timeout: 10000,
  defaultValue: [],
})
```

#### `initRouteContext`

```typescript

```

| 파라미터 | 타입 | 설명 |
|----------|------|------|
| `route` | `RouteLocationNormalizedLoaded` | Vue Router의 현재 route 객체 |

SSR에서 외부 유틸 함수(`isCurrentSnb`, `isActiveMenu` 등)가 현재 경로를 안전하게 참조할 수 있도록 모듈 레벨 변수에 route를 저장한다. setup 컨텍스트 내에서 반드시 먼저 호출해야 한다.

```typescript

```

---

#### `getHrefFromMenu`

```typescript
export function getHrefFromMenu(menu: MenuItem, opts?: HrefOpts): string
```

| 파라미터 | 타입 | 설명 |
|----------|------|------|
| `menu` | `MenuItem` | 대상 메뉴 객체 |
| `opts.preferChild` | `boolean` | link 타입도 하위 첫 콘텐츠 경로를 우선 시도 |

메뉴 타입별 이동 경로를 계산한다.

- `link` → `menu.value`를 외부 URL로 반환 (도메인만 오면 `http://` 자동 보정)
- `folder` → 하위에서 첫 번째로 노출 가능한 콘텐츠의 `routePath`
- 그 외 (`board`, `content`, `script`) → `menu.routePath` 또는 `pathUrl` 파싱 결과

**반환값**: `string` — 이동 경로 (없으면 `""`)

```typescript
const href = getHrefFromMenu(menuItem)
// → "/jh/notify/list" 또는 "https://external.com"
```

#### `linkHref`

```typescript
export function linkHref(menu: MenuItem): string
```

| 파라미터 | 타입 | 설명 |
|----------|------|------|
| `menu` | `MenuItem` | link 타입 메뉴 객체 |

`link` 타입 메뉴의 실제 href를 계산한다.

- `menu.value`가 있으면 `normalizeLinkValue()`로 정규화
- `menu.value`가 없으면 `getHrefFromMenu(menu)`로 폴백
- `javascript:`, `data:` 스킴은 빈 문자열 반환 (XSS 차단)
- 도메인만 있으면 `http://` 자동 보정

**반환값**: `string`

```typescript
const href = linkHref(menu)
// → "https://www.example.com" 또는 "/jh/notify"
```

#### `newWinId`

```typescript
export function newWinId(
  menu: Pick<MenuItem, 'id'> | { id?: number | string } | null,
  prefix?: string
): string
```

| 파라미터 | 타입 | 기본값 | 설명 |
|----------|------|--------|------|
| `menu` | 메뉴 객체 | — | id 필드만 사용 |
| `prefix` | `string` | `"nw"` | ID 접두사 |

스크린리더용 "새 창에서 열림" 안내 요소의 고유 ID를 생성한다. `aria-describedby` 속성에 사용한다.

**반환값**: `string` — `"nw-{menu.id}"` 형태

```typescript
const descId = newWinId(menu)
// → "nw-42"

// 사용 예
<a :href="linkHref(menu)" target="_blank" :aria-describedby="newWinId(menu)">
  {{ menu.name }}
</a>
<span :id="newWinId(menu)" class="sr-only">새 창에서 열림</span>
```

## 3. 유효성 검증

### validator.ts

**파일**: `utils/validator.ts`

폼 입력값 유효성 검증 함수 모음. DOMPurify 기반 HTML 살균(sanitize), SQL Injection/XSS 패턴 차단, 타입별 길이 제한을 일관되게 적용한다.

---

#### `validateInput`

```typescript
export const validateInput = (options: ValidationOptions): string | null
```

**ValidationOptions 파라미터**

| 옵션 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `fieldName` | `string` | — | 에러 메시지에 표시할 필드명 |
| `value` | `string` | — | 검사할 값 |
| `required` | `boolean` | `true` | 필수 여부 |
| `minLength` | `number` | 타입별 기본값 | 최소 길이 |
| `maxLength` | `number` | 타입별 기본값 | 최대 길이 |
| `allowTags` | `boolean` | `false` | HTML 태그 허용 여부 |
| `allowScript` | `boolean` | `false` | 위험 스크립트 태그 허용 여부 |
| `type` | `ValidationType` | `"default"` | 검증 타입 |

**ValidationType 별 기본 길이**

| type | minLength | maxLength | 용도 |
|------|-----------|-----------|------|
| `default` | 1 | 50 | 제목, 이름, 부서명 등 일반 필드 |
| `text` | 1 | 1000 | 설명, 메모 등 긴 텍스트 |
| `html` | 1 | 10000 | 에디터 본문 (DOMPurify 살균 적용) |
| `email` | 5 | 254 | 이메일 주소 |
| `phone` | 7 | 20 | 한국 전화번호 |
| `url` | 5 | 2048 | URL |

**반환값**: `string | null` — 에러 메시지 문자열 또는 통과 시 `null`

```typescript
const err = validateInput({
  fieldName: '제목',
  value: formData.title,
  type: 'default',
})
if (err) return showAlertMessage('COMMON.VALIDATION.REQUIRED', { field: '제목' })
```

#### `validateFiles`

### authBus.ts

**파일**: `utils/authBus.ts`

같은 브라우저의 여러 탭/창 간에 인증 상태 변화를 실시간으로 동기화하는 이벤트 버스이다.

**설계 특징**
- BroadcastChannel 우선 사용, 미지원 브라우저는 `localStorage` storage 이벤트로 폴백
- `TAB_ID`로 자신이 보낸 이벤트는 무시 (루프 방지)
- `start()`는 중복 호출 안전 (HMR 대응)

---

#### `AuthEvent` 타입

```typescript
type AuthEvent =
  | { type: "LOGIN"; from: string; ts: number }
  | { type: "LOGOUT"; from: string; ts: number }
  | { type: "PROFILE_UPDATED"; from: string; ts: number }
```

---

#### 인스턴스 메서드 (`authBus`)

| 메서드 | 시그니처 | 설명 |
|--------|----------|------|
| `start` | `() => void` | 리스너 초기화 (1회만 연결). `plugins/*.client.ts`에서 호출 권장 |
| `stop` | `() => void` | 리스너 해제 및 BroadcastChannel 정리 |
| `on` | `(listener: (evt: AuthEvent) => void) => () => void` | 이벤트 구독. 반환값은 구독 해제 함수 |
| `post` | `(type: AuthEvent['type']) => void` | 이벤트 발행 (다른 탭에 브로드캐스트) |
| `tabId` | `string` (getter) | 현재 탭 고유 ID |

```typescript

import { authBus } from '~/utils/authBus'
export default defineNuxtPlugin(() => {
  authBus.start()
})

// stores/userStore.ts - 다른 탭의 인증 변화 구독
authBus.on((evt) => {
  if (evt.type === 'LOGOUT') clearUser()
  if (evt.type === 'LOGIN') fetchCurrentUser()
})

// useAuth.ts - 로그인/로그아웃 후 발행
await login(credentials)
authBus.post('LOGIN')

await logout()
authBus.post('LOGOUT')
```
