# 테마 개발 가이드

## 1. 테마 시스템 개요

Q-CMS의 게시판은 **테마** 단위로 UI를 관리한다. 게시판 타입과 테마 이름의 조합으로 화면을 결정하며, 관리자가 게시판 생성 시 테마를 선택한다.

### 테마 타입

| 타입 | 설명 | boardType 예시 |
|---|---|---|
| list | 테이블 형태의 일반 게시판 | `LIST.default`, `LIST.qna` |
| gallery | 썸네일 기반 이미지 갤러리 | `GALLERY.default` |
| flow | 단계(step) 기반 워크플로우 | `FLOW.default` |
| content | 컨텐츠 페이지 (테마 없음) | - |

boardType 형식: `{타입(대문자)}.{테마이름}` (예: `LIST.default`, `GALLERY.default`)

## 2. 테마 파일 구조

### metadata.json

테마의 메타정보와 지원 옵션을 정의한다. 관리자 화면에서 게시판 옵션 토글을 이 파일 기준으로 렌더링한다.

```json
{
  "name": "default",
  "displayName": "기본 리스트 테마",
  "description": "공공기관 스타일의 기본 리스트 테마",
  "options": [
    { "field": "isAdminReply", "label": "담당자 답변" },
    { "field": "isThreadReply", "label": "답변글 계층" },
    { "field": "isPrivate", "label": "공개/비공개" },
    { "field": "isPrivateDefault", "label": "기본 비공개", "parent": "isPrivate" },
    { "field": "isUsePeriod", "label": "게시 기간" },
    { "field": "isTopFixed", "label": "상단 고정" },
    { "field": "isAuthorOnly", "label": "내 글만 보기" },
    { "field": "isMaskAuthor", "label": "작성자 마스킹" },
    { "field": "newBadgeDays", "label": "새글 표시 기간(일)", "type": "number" },
    { "field": "isAttached", "label": "첨부파일" },
    { "field": "authorDisplayType", "label": "등록자 표시 방식", "type": "select" },
    { "field": "isAdminApproval", "label": "관리자 승인" },
    { "field": "isViewImageDisplay", "label": "본문 이미지 출력", "parent": "isAttached" }
  ]
}
```

**필드 설명:**

| 필드 | 타입 | 설명 |
|---|---|---|
| name | string | 테마 식별자 (폴더명과 동일) |
| displayName | string | 관리자 화면에 표시되는 이름 |
| description | string | 테마 설명 |
| options | array | 지원하는 옵션 목록 |
| options[].field | string | 옵션 키 (boardOption에서 조회) |
| options[].label | string | 관리자 UI에 표시되는 라벨 |
| options[].type | string | `"number"`, `"select"` 등 (기본: toggle) |
| options[].parent | string | 부모 옵션 (부모가 ON일 때만 표시) |

### Loader.vue 역할

Loader.vue는 두 가지 역할을 한다.

1. **기본 컴포넌트(Ori.vue) 로드**
2. **override 감지**: `overrides/` 폴더에서 메뉴 ID와 일치하는 Vue 파일이 있으면 Ori.vue 대신 해당 파일을 렌더링

```vue
<script setup lang="ts">
import Ori from "./Ori.vue";
import { useMenuOverride } from "~/composables/api/render/useMenuOverride";

const overrideModules = import.meta.glob("./overrides/*.vue", { eager: true });
const { resolvedComponent } = useMenuOverride(Ori, overrideModules);
</script>

<template>
  <component :is="resolvedComponent" />
</template>
```

모든 Loader.vue는 위 구조를 동일하게 사용한다. 새 테마를 만들 때 그대로 복사하면 된다.

### Ori.vue 역할

Ori.vue는 실제 HTML/CSS 렌더링을 담당한다. 핵심 규칙은 다음과 같다.

- `inject(boardCoreKey)`로 게시판 데이터를 주입받는다
- `common/` 공통 컴포넌트를 조합하여 화면을 구성한다
- HTML 구조와 CSS 클래스만 변경하므로 퍼블리셔가 직접 수정할 수 있다

### overrides/{menuId}.vue

특정 메뉴에만 다른 디자인을 적용할 때 사용한다. 파일명은 메뉴 ID (숫자)로 지정한다.

```
overrides/
├── 1001.vue    ← 메뉴 ID 1001에만 적용
└── 1025.vue    ← 메뉴 ID 1025에만 적용
```

## 3. 새 테마 만들기 (Step-by-step)

예시: `list/notice` 테마를 만든다고 가정한다.

### Step 1: 폴더 생성

```
components/theme/list/notice/
├── metadata.json
├── list/
│   ├── Loader.vue
│   ├── Ori.vue
│   └── overrides/          (빈 폴더, 필요 시 override 추가)
├── view/
│   ├── Loader.vue
│   └── Ori.vue
└── write/
    ├── Loader.vue
    └── Ori.vue
```

### Step 2: metadata.json 작성

테마가 지원할 옵션만 골라서 작성한다.

```json
{
  "name": "notice",
  "displayName": "공지사항 테마",
  "description": "상단고정과 첨부파일을 지원하는 공지사항 전용 테마",
  "options": [
    { "field": "isTopFixed", "label": "상단 고정" },
    { "field": "isUsePeriod", "label": "게시 기간" },
    { "field": "isAttached", "label": "첨부파일" },
    { "field": "newBadgeDays", "label": "새글 표시 기간(일)", "type": "number" },
    { "field": "authorDisplayType", "label": "등록자 표시 방식", "type": "select" }
  ]
}
```

### Step 3: Loader.vue 복사

list, view, write 각 폴더에 동일한 Loader.vue를 생성한다. 내용은 모두 같다.

```vue
<script setup lang="ts">
import Ori from "./Ori.vue";
import { useMenuOverride } from "~/composables/api/render/useMenuOverride";

const overrideModules = import.meta.glob("./overrides/*.vue", { eager: true });
const { resolvedComponent } = useMenuOverride(Ori, overrideModules);
</script>

<template>
  <component :is="resolvedComponent" />
</template>
```

### Step 4: Ori.vue 작성 (목록 화면)

`list/Ori.vue` 작성 예시. 공통 컴포넌트를 조합하고 컬럼을 정의한다.

```vue
<template>
  <div>
    <!-- 검색영역 -->
    <themeCommonListSearchBox />

    <!-- 정렬영역 -->
    <themeCommonListSortArea />

    <!-- 게시판 테이블 -->
    <themeCommonListBoardTable :items="boardList" :columns="columns" />

    <!-- 페이지네이션 -->
    <themeCommonListPagination />

    <!-- 목록 하단 액션 -->
    <themeCommonListActionButton />
  </div>
</template>

<script setup lang="ts">
import { inject } from "vue";
import { boardCoreKey } from "~/composables/api/render/useBoard";
import { useBoardOptionHelpers } from "~/composables/api/render/useBoardOptionHelpers";
import { formatDateSmart, formatNumber } from "~/utils/date";
import type { BoardTableColumn } from "~/components/theme/common/list/BoardTable.vue";

const board = inject(boardCoreKey)!;
const { boardList, boardOption, fieldDefs } = board;
const { formatAuthor } = useBoardOptionHelpers(boardOption, fieldDefs);

const columns: BoardTableColumn[] = [
  { key: "idx", label: "번호", class: "web_only" },
  { key: "title", label: "제목", class: "align_left", isTitle: true },
  {
    key: "author",
    label: "등록자",
    valueGetter: (item) => item,
    formatter: formatAuthor,
  },
  { key: "createdDate", label: "등록일", formatter: formatDateSmart },
  {
    key: "viewCount",
    label: "조회수",
    class: "web_only",
    formatter: formatNumber,
  },
];
</script>
```

**컬럼 정의 (BoardTableColumn) 인터페이스:**

| 필드 | 타입 | 설명 |
|---|---|---|
| key | string | 데이터 필드명 (BoardListItem의 프로퍼티) |
| label | string | 테이블 헤더에 표시될 텍스트 |
| class | string | td에 적용할 CSS 클래스 (`web_only`, `align_left`) |
| isTitle | boolean | true이면 제목 컬럼 (링크, 비공개/신규/답글 아이콘 자동 처리) |
| formatter | function | 셀 값 포맷 함수 (`formatDateSmart`, `formatNumber` 등) |
| valueGetter | function | item에서 커스텀 값 추출 (기본: `item[key]`) |

### Step 5: 관리자에서 게시판에 테마 적용

관리자 > 게시판 관리 > 해당 게시판 설정에서 boardType을 `LIST.notice`로 설정한다.

## 5. Override 메커니즘

### 동작 원리

Loader.vue에서 `import.meta.glob("./overrides/*.vue", { eager: true })`로 overrides 폴더의 모든 Vue 파일을 빌드 타임에 수집한다.

`useMenuOverride` 컴포저블이 현재 메뉴 ID와 파일명을 비교하여 일치하는 컴포넌트가 있으면 Ori.vue 대신 렌더링한다.

```typescript
// useMenuOverride.ts 핵심 로직
export function useMenuOverride(
  defaultComp: Component,
  overrideModules: Record<string, any>
) {
  const menuStore = useMenuStore();
  const menuId = menuStore.currentMenuId;

  const componentMap: Record<string, Component> = {};

  for (const path in overrideModules) {
    const mod = overrideModules[path];
    const file = path.split("/").pop()?.replace(".vue", "");
    if (file && mod?.default) {
      componentMap[file] = mod.default;
    }
  }

  const resolvedComponent = computed(() => {
    const key = String(menuId ?? "");
    return componentMap[key] ?? defaultComp;
  });

  return { resolvedComponent };
}
```

### Override 파일 만드는 방법

1. 관리자에서 해당 게시판의 메뉴 ID를 확인한다 (예: 1001)
2. 해당 테마의 모드(list/view/write) 폴더에 `overrides/` 디렉토리를 만든다
3. `overrides/1001.vue` 파일을 생성한다
4. Ori.vue를 복사하여 원하는 부분만 수정한다

```
list/default/list/
├── Loader.vue
├── Ori.vue
└── overrides/
    └── 1001.vue    ← 메뉴 1001에서만 사용
```

override 파일은 Ori.vue와 동일한 구조로 작성한다. inject, 공통 컴포넌트 등 모두 동일하게 사용할 수 있다.

## 6. CSS 클래스 가이드 (사용자 사이트)

**Tailwind는 business(관리자) 사이트에서만 사용한다. 사용자 사이트의 테마에서는 전통 CSS 클래스를 사용한다.**

### 버튼

```
기본 구조: btn_base {크기} {타입} {배경/테두리}

크기: sm | md | lg | xlg | xsm
타입: tp1 ~ tp7
배경: bg_primary50 | bg_secondary | bg_tertiary | bg_gray0
테두리: line_gray30 | line_secondary | line_tertiary | line_danger
모서리: br0 (각진), br50 (원형)
```

| 클래스 | 설명 | 실제 사용 예 |
|---|---|---|
| `btn_base` | 기본 버튼 | `<button class="btn_base xlg tp1 bg_tertiary br0">` |

import { inject } from "vue";
import { boardCoreKey } from "~/composables/api/render/useBoard";

const board = inject(boardCoreKey)!;

플로우 테마 전용 컨텍스트. 단계 관련 데이터를 제공한다.

### useBoardOptionHelpers

boardOption과 fieldDefs를 기반으로 옵션 조회, 새글 판별, 작성자 포맷 등의 헬퍼를 제공한다.

```typescript
import { useBoardOptionHelpers } from "~/composables/api/render/useBoardOptionHelpers";

const { opt, isNewPost, formatAuthor, splitTopFixed } =
  useBoardOptionHelpers(boardOption, fieldDefs);

// 옵션 확인
if (opt("isPrivate")) { /* 비공개 기능 활성화 */ }
if (opt("isTopFixed")) { /* 상단고정 활성화 */ }

// 새글 판별
isNewPost(item.createdDate)  // boolean

// 작성자 포맷 (마스킹 등)
formatAuthor(item)  // string

// 상단고정 분리
const { topFixed, normal } = splitTopFixed(items);
```

### QnA 테마 - 변형 예시 참고

QnA 테마(`list/qna/`)는 BoardTable 대신 아코디언(`faq_list`)을 직접 구현한 변형 사례다. view 모드 없이 목록에서 바로 내용을 펼쳐 보여준다. 새 테마에서 기존 공통 컴포넌트와 다른 UI가 필요하면 QnA 테마처럼 Ori.vue에 직접 HTML을 작성하면 된다.
