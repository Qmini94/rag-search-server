# Nuxt 플러그인 · 서버 미들웨어

## 개요

Nuxt 3 프론트엔드의 플러그인(`plugins/`) 4개, 서버 미들웨어(`server/middleware/`) 2개, 서버 API 라우트(`server/api/`) 4개, 서버 유틸(`server/utils/`) 2개를 정의한다.
플러그인은 `.server.ts` / `.client.ts` 접미사로 실행 환경이 분리된다.

---

## 1. 플러그인

### 1-1. `plugins/init.server.ts` — SSR 초기화

**목적**: SSR 요청 중 정적 파일 / 업로드 파일 경로를 감지하여 SSR 초기화를 건너뛰고, HTML 페이지 요청에 한해 클라이언트 IP를 전역 상태(`useState`)에 주입한다.

#### 스킵 패턴 3계층

| 계층 | 변수명 | 예시 |
|---|---|---|
| 무조건 통과 경로 | `IGNORE_PATH_PATTERNS` | `/.well-known/`, `/_nuxt/`, `favicon.ico`, `robots.txt`, `sitemap.xml`, `manifest.webmanifest`, `service-worker.js` |
| 정적/업로드 프리픽스 | `STATIC_PREFIXES` | `/contents/`, `/uploads/`, `/files/`, `/images/`, `/assets/` |
| 파일 확장자 | `STATIC_EXTS` | `.png .jpg .webp .avif .gif .svg .ico .css .js .mjs .map .pdf .wasm .woff2 .ttf .mp4` 등 |

세 계층 중 하나라도 매칭되면 `return` (초기화 전체 스킵).

#### 환경별 역할 차이

- **로컬 개발**: Nuxt dev 서버가 `/public`을 직접 서빙하므로, 이 플러그인이 정적 경로 SSR 비용을 방지한다.
- **운영(배포)**: 아파치가 `ProxyPass /contents/cms/ !` + `Alias` 로 Nuxt 를 거치지 않고 직접 서빙한다. 플러그인이 있어도/없어도 무해하며 오버헤드 방지 가드 역할만 한다.

#### 경로 파싱

```ts
const rawUrl = req?.url || ev?.path || "/";
path = new URL(rawUrl, "http://localhost").pathname;
// 실패 시: rawUrl.split("#")[0].split("?")[0]
```

쿼리스트링(`?v=123` 캐시버스터 등)과 해시를 제거한 순수 `pathname` 기준으로 매칭한다.

#### HEAD / OPTIONS 처리

```ts
if (method === "HEAD" || method === "OPTIONS") return;
```

비콘텐츠 메서드는 조건 검사 없이 통과시킨다.

#### 클라이언트 IP 주입

```ts
const forwardedFor = req?.headers?.["x-forwarded-for"] || "";
const clientIp = forwardedFor.split(",")[0]?.trim()
  || req?.socket?.remoteAddress || "";
// "::ffff:" IPv4-mapped IPv6 접두어 제거
useState("client_ip", () => clientIp.replace("::ffff:", ""));
```

`X-Forwarded-For` 헤더(프록시 환경)를 우선하고, 없으면 소켓 주소를 사용한다. IPv4-mapped IPv6(`::ffff:x.x.x.x`)는 순수 IPv4로 정규화한다.

### 1-2. `plugins/color-mode-www.client.ts` — 다크모드 제한

**목적**: `business` 레이아웃을 제외한 모든 레이아웃에서 다크모드를 강제로 `light`로 고정한다.

```ts
watch(
  () => route.meta.layout as string | undefined,
  (layout) => {
    if (!layout?.startsWith("business")) {
      colorMode.preference = "light";
    }
  },
  { immediate: true },
);
```

- `immediate: true` 덕분에 최초 마운트 시 즉시 평가된다.
- `business` 레이아웃(관리자 영역)만 사용자의 시스템 다크모드를 따른다.
- 공공 사이트(www) 레이아웃은 항상 라이트 모드로 고정된다.

### 1-3. `plugins/ssr-msg.client.ts` — URL 메시지 처리

**목적**: 백엔드 리다이렉트 후 URL에 붙어 오는 `?msg=KEY` 쿼리를 감지하여 브라우저 alert으로 출력하고, query에서 `msg`를 제거한다.

#### 흐름

```
URL: /some/page?msg=AUTH.LOGIN.SUCCESS&other=1
  → key = "AUTH.LOGIN.SUCCESS"
  → showAlertMessage(key)  // window.alert(UI_MESSAGES_KO[key])
  → router.replace({ query: { other: "1" } })  // msg만 제거
```

#### 사용하는 메시지 키 범주 (`UiMessageKey`)

`utils/uiMessages.ko.ts`의 `UI_MESSAGES_KO` 객체 전체가 사용 가능한 키다.
`?msg=` 로 실제로 붙는 주요 키:

| 키 | 메시지 |
|---|---|
| `AUTH.LOGIN.SUCCESS` | 로그인 되었습니다. |
| `AUTH.LOGOUT.SUCCESS` | 로그아웃 되었습니다. |
| `AUTH.ADMIN.ONLY` | 관리자만 접근 가능합니다. |
| `AUTH.ADMIN.ONLY.LOGIN` | 관리자만 접근 가능합니다. 로그인해 주세요. |
| `PERMISSION.DENIED.USER` | 권한이 없습니다. |
| `PERMISSION.DENIED.GUEST` | 권한이 없습니다. 로그인을 해주세요. |
| `BOARD.ACCESS.DENIED` | 잘못된 접근입니다. |

#### `?msg=` 를 붙이는 곳

미들웨어(`middleware/01~05-*.ts`) 또는 백엔드 리다이렉트 응답에서 `router.replace` / `navigateTo` 호출 시 쿼리에 추가한다.

#### 참고 — `showAlertMessage` 내부

```ts
// utils/uiMessage.ts
export function showAlertMessage(key: UiMessageKey, params?: UiMessageParams): void {
  const message = formatUiMessage(key, params);  // 플레이스홀더 치환
  window.alert(message);
}
```

`UI_MESSAGES_KO[key]`를 기반으로 `{field}`, `{min}`, `{max}` 플레이스홀더를 치환하여 출력한다.

### 1-4. `plugins/vue-query.client.ts` — TanStack Query 전역 설정

**목적**: `@tanstack/vue-query`를 Nuxt 앱에 등록하고, CMS 특성에 맞는 전역 쿼리 기본값을 설정한다.

```ts
nuxtApp.vueApp.use(VueQueryPlugin, {
  queryClientConfig: {
    defaultOptions: {
      queries: {
        refetchOnWindowFocus: false,   // 탭 포커스 복귀 시 재요청 안 함
        refetchOnReconnect: false,     // 네트워크 복구 시 재요청 안 함
        refetchOnMount: false,         // 마운트 시 자동 재검증 안 함
        staleTime: Infinity,           // 항상 신선 취급 → 자동 재검증 없음
        retry: 0,                      // 실패 시 재시도 없음
        gcTime: 5 * 60 * 1000,        // 5분 후 캐시 GC
      },
    },
  },
})
```

#### 옵션 선택 이유

| 옵션 | 값 | 이유 |
|---|---|---|
| `staleTime: Infinity` | 무한 | CMS 메뉴/콘텐츠는 관리자가 명시적으로 갱신 — 자동 재검증 불필요 |
| `refetchOnWindowFocus: false` | false | 탭 전환마다 API 호출하면 SSR 캐시와 충돌 가능 |
| `refetchOnReconnect: false` | false | 네트워크 복구 시 의도치 않은 재렌더링 방지 |
| `refetchOnMount: false` | false | 컴포넌트 재마운트(페이지 전환) 시 캐시 데이터가 있으면 재사용 |
| `retry: 0` | 0 | 실패한 API를 자동 재시도하면 서버 부하 유발 가능, 에러 처리를 명시적으로 |
| `gcTime: 5 * 60 * 1000` | 5분 | 메모리 누수 방지를 위한 미사용 캐시 정리 |

## 2. 서버 미들웨어

### 2-1. `server/middleware/css-version.ts` — CSS 버전 주입

**목적**: 모든 SSR 응답의 `event.context`에 `cssVersion`을 주입하여 composable / 레이아웃에서 CSS 캐시 버스팅에 사용한다.

```ts
export default defineEventHandler(async (event) => {
  const url = event.node.req.url || "";
  if (
    url.startsWith("/api/") ||
    url.startsWith("/_nuxt/") ||
    url.startsWith("/public/")
  ) {
    return;  // API/정적 요청 스킵
  }
  event.context.cssVersion = await getCssVersion();
});
```

composable에서는 다음과 같이 접근한다:

```ts
useNuxtApp().ssrContext?.event.context.cssVersion
```

### 2-2. `server/middleware/security-headers.ts` — 보안 헤더

**목적**: HTML 페이지 응답에 CSP를 포함한 보안 헤더 일체를 추가한다.

#### 스킵 조건

API(`/api/`), Nuxt 번들(`/_nuxt/`), 정적 파일(`/public/images/`, `/public/style/`, `/public/`), JS/CSS/이미지 확장자 포함 URL.

#### CSP (Content-Security-Policy)

환경(`process.env.NODE_ENV`)에 따라 directive가 달라진다.

| directive | 개발 | 운영 |
|---|---|---|
| `script-src` | `'self' 'unsafe-inline' 'unsafe-eval' 'wasm-unsafe-eval' *` | `'self' 'unsafe-inline'` + jsdelivr, unpkg, Daum/Kakao 우편번호 CDN |
| `style-src` | `'self' 'unsafe-inline' *` | `'self' 'unsafe-inline'` + Google Fonts, jsdelivr |
| `connect-src` | `'self' *` | `'self' {baseUrl} {apiBase} ws://localhost:* wss://localhost:*` |

공통 directive:

```
font-src    'self' https://fonts.gstatic.com https://cdn.jsdelivr.net data:
img-src     'self' data: https: blob:
media-src   'self' data: blob:
object-src  'none'
frame-src   'self' https://postcode.map.kakao.com http://postcode.map.kakao.com https://*.kakao.com http://*.kakao.com
worker-src  'self' blob:
child-src   'self' https://postcode.map.kakao.com ...
form-action 'self'
base-uri    'self'
manifest-src 'self'
```

#### 기타 보안 헤더

| 헤더 | 값 | 목적 |
|---|---|---|
| `X-Frame-Options` | `DENY` | 클릭재킹 방지 |
| `X-Content-Type-Options` | `nosniff` | MIME 타입 스니핑 방지 |
| `X-XSS-Protection` | `1; mode=block` | 구형 브라우저 XSS 필터 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 리퍼러 정보 제한 |
| `Permissions-Policy` | `geolocation=(), microphone=(), camera=(), payment=(), usb=(), magnetometer=(), accelerometer=(), gyroscope=()` | 브라우저 기능 비활성화 |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains; preload` | HTTPS 강제 (운영 환경만) |
| `Cross-Origin-Embedder-Policy` | `unsafe-none` | 외부 CDN/iframe(다음 우편번호) 허용 |
| `Cross-Origin-Opener-Policy` | `same-origin-allow-popups` | 우편번호 검색 팝업 허용 |
| `Cross-Origin-Resource-Policy` | `cross-origin` | 외부 리소스 로드 허용 |
| `Server` | `Web Server` | 서버 정보 은닉 |
| `X-Powered-By` | `""` (제거) | 기술 스택 노출 방지 |

개발 환경에서는 `X-Security-Headers: enabled` 헤더가 추가된다.

## 4. 서버 유틸

### 4-1. `server/utils/fetchJsonData.ts` — 파일시스템 vs HTTP 분기

**목적**: 환경변수 `CMS_JSON_ROOT` 유무에 따라 JSON 데이터 소스를 분기한다.

```ts
const JSON_ROOT = process.env.CMS_JSON_ROOT;

export async function fetchJsonData(domain: string, fileName: string): Promise<any> {
  if (JSON_ROOT) {
    // 배포 환경: 파일시스템 직접 읽기
    const filePath = path.join(JSON_ROOT, domain, fileName);
    return JSON.parse(await fs.readFile(filePath, "utf-8"));
  }

  // 로컬 개발: CMS_BASE_URL로 HTTP 호출
  const baseUrl = process.env.CMS_BASE_URL?.replace(/\/+$/, "");
  if (!baseUrl) throw new Error("CMS_JSON_ROOT 또는 CMS_BASE_URL 환경변수가 필요합니다.");

  const url = `${baseUrl}/cms/json/${domain}/${fileName}`;
  const res = await fetch(url, { method: "GET", headers: { "Content-Type": "application/json" } });
  if (!res.ok) throw new Error(`Failed to fetch: ${url}`);
  return await res.json();
}
```

#### 환경별 전략

| 환경 | `CMS_JSON_ROOT` | 동작 | 이유 |
|---|---|---|---|
| 배포(운영/스테이징) | 설정됨 (예: `/data/cms/json`) | `fs.readFile` 직접 읽기 | 네트워크 왕복 없이 빠름, 백엔드 부하 없음 |
| 로컬 개발 | 미설정 | `fetch(CMS_BASE_URL/cms/json/...)` HTTP 호출 | JSON 파일을 로컬에 두지 않고 개발 백엔드에서 실시간 제공 |

URL 패턴: `{CMS_BASE_URL}/cms/json/{domain}/{fileName}`
예: `http://localhost:8080/cms/json/menu/active.json`

### 4-2. `server/utils/cssVersion.ts` — CSS 버전 캐시

**목적**: `/public/css-version.json`에서 CSS 빌드 버전을 읽어 10초 메모리 캐시로 제공한다.

```ts
let cachedVersion = "";
let cacheTimestamp = 0;
const CACHE_TTL_MS = 10_000; // 10초

export async function getCssVersion(): Promise<string> {
  const now = Date.now();
  if (cachedVersion && now - cacheTimestamp < CACHE_TTL_MS) {
    return cachedVersion;  // 캐시 히트
  }

  try {
    const data: any = await $fetch("/public/css-version.json", {
      baseURL: useRuntimeConfig().public.baseUrl as string,
      timeout: 3000,
    });
    if (data?.version) {
      cachedVersion = data.version;
    }
  } catch {
    // 실패 시 이전 값 유지 (빈 문자열이면 "0" 반환)
  }

  cacheTimestamp = now;
  return cachedVersion || "0";
}
```

#### 동작 특성

| 항목 | 내용 |
|---|---|
| TTL | 10초 (`CACHE_TTL_MS = 10_000`) |
| 캐시 저장소 | Node.js 프로세스 메모리 (모듈 스코프 변수) |
| 요청 방식 | `$fetch` (Nuxt의 ofetch 래퍼) → nginx가 `/public/` 서빙 |
| timeout | 3,000ms |
| 실패 처리 | 예외를 무시하고 이전 `cachedVersion` 값을 유지. 최초 실패 시 `"0"` 반환 |
| 타임스탬프 갱신 | 성공/실패 무관하게 `cacheTimestamp = now` 갱신 → 10초 동안 재시도 안 함 |

이 버전 값은 `server/middleware/css-version.ts`를 통해 `event.context.cssVersion`으로 주입되며, 레이아웃 컴포넌트에서 `<link rel="stylesheet" href="/style/main.css?v={cssVersion}">` 형태로 사용된다.
